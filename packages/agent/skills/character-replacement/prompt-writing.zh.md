# 提示词写法

## 最高原则

**写清哪个源人物对应哪张肖像、要换哪些特征，表演、镜头和场景交给源片，关键遮挡只用一句话说明谁挡在谁前面。**

新写和修改提示词时，先按这条原则判断该写什么。范本、示例和上游指南的用法均以此为准。

生成提示词用英文，说明用用户的语言。Agent 快照中的同级目录 `../h3-prompt-writing/SKILL.md` 和 `../h3-prompt-writing/references/ref-en.txt`（源码目录位于 `.agents/upstream/minimax-h3/skills/h3-prompt-writing`）仅用于查阅字段名和标签语法。换人提示词的内容按本 skill 编写。

## 写提示词前先做计划

新素材或新的多段工作流，先完成[镜头时间线、人物可见性时间线和分段计划](video-segment.zh.md)。修正已有片段时，先检查相关画面。只有边界或人物对应关系需要修正时才改计划。

## 建立人物对应关系

检查源视频和实际按顺序传入的参考图。无法检查素材时，说明限制，按用户明确指定的对应关系填写。有歧义时请用户确认。

- 每张实际绑定的肖像对应一个 `<Subject N>:`。同一行同时写明目标肖像和源人物的已核实识别线索，摘要说明替换范围以及沿用源片表演。
- 为每位源人物记录一个能辨认身份的帧。只在核实过的同框镜头中用左右定位，并辅以发型、眼镜等线索。即使特征要由肖像替换，也可以用原特征辨认源人物。切镜、单人镜头和重新入画时沿用同一对应关系。单人镜头用已核实的源人物特征指认当前可见的人；双人镜头里的左右位置只记录在计划的人物映射中。
- 同一张图有多人且目标不明确时，裁出指定人物，保留所需特征，并满足模型的输入尺寸要求。绑定前检查最终裁剪图，FastH3 参考图的两边须为 256–5760 像素，宽高比须为 0.4–2.5。必要时使用更清楚的参考图。同一人的多个视角只定义一个目标身份。

## 确定替换范围

优先使用用户提供的提示词或明确指定的特征。用户只说「换脸」时，用肖像的脸、发型和眼镜，包括戴或不戴眼镜；服装、身体、表演和场景沿用源视频。用户要求「只换脸」时保留源发型和眼镜，要求「保留原发型」时仅覆盖发型规则。

用户要求换人且未指定具体特征时，采用指定肖像的外观。把替换范围写进计划，提示词各节采用同一范围。

保留的衣物或配饰如果直接影响可见动作，在对应轨迹的 `retainedDetails` 中填入已核实的源特征描述，动作本身仍以源片为准。

换脸或头部替换时，从原始肖像矩形裁出目标人物的完整头部。给发顶、两侧、耳朵、下巴和可见长发留出余量，裁切边界避开人物头部轮廓。边缘可以保留背景、衣领或少量肩部，禁止抠图、圆形蒙版和填灰底。原图已缺失所需特征时，使用更完整的参考图。替换服装或整个人物外观时，保留能展示全部所需特征的参考范围。

绑定前查看实际裁切图，确认所需特征完整且符合模型输入要求。将裁切图登记为原图的衍生素材，在分段计划注明来源，并在发布前回读有序肖像引用，核对素材 ID 和版本。

## 组织提示词

新素材通过[换人预检](workflow.zh.md#发布并核对计划)生成提示词。预检按源片检查记录和实际送模区间派生 `tracks`、`shotSubjects` 和 `timelineGuides`，计入额外上下文和倒放。`prompt-options.json` 只填范围、原声等可选设置。填写遮挡物时，在 `occludedFaceRanges` 写明 `object` 和落在实际窗口内的 `evidenceFrames`。下文说明生成模板。成片音轨在时间线上设置。

**生成提示词禁止使用分镜指令，无论是否带时间码。** 指挥开场、切镜、重排镜头，或编排动作、运镜、构图、灯光和背景，都可能诱导 H3 重绘画面。时间码和帧号留在分段计划、导帧设置和裁切设置中。

在 `detailed_description` 中，由 `<Video 1>` 提供表演、镜头和场景。检查实际送入模型的片段首尾帧，以及相关切点两侧的画面。`[Shot N]` 只用于标记源片已有的镜头，并写明该镜头的源人物轨迹和肖像对应关系。定义源人物轨迹后，在编辑指令里用人物标签指代；原发型等将被替换的识别线索只写在轨迹定义里。范围外的服饰和道具统一交给源视频；替换范围限于头部时，保留条目和编辑指令不单独罗列服饰道具，除非用户明确要求控制，或该物件直接造成保留画面中已核实的遮挡。检查到前景物件遮住替换区域时，通过 `foregroundOccluder` 点名一次，明确它在源片中遮住人物时挡在替换后人物前面；物件动作和可见时机由源视频决定。服装和道具清单留在计划里。

切镜改变可见人物时，在该 `[Shot N]` 行写明每个可见待换人物的源轨迹及对应肖像。单人特写只写该人物的轨迹和肖像。人物在镜头内离开时，让其替换后的外观随对应轨迹出画。

### 构建节点提示词

`build_head_prompts.py` 先校验结构化输入，再渲染[六段固定 Jinja 模板](scripts/head_prompt.jinja)。Jinja2 随 OpenDirector 安装。

运行 `opendirector skill-script character-replacement/scripts/build_head_prompts.py prompt-inputs.json > prompts.json`（传入 `-` 可从标准输入读取同一份 JSON）。标准输出返回片段 ID 到完整提示词的映射，例如：

```json
{"S1":{"tracks":["left performer in a green jacket","right performer in a red jacket"],"sourceAudio":true,"shotSubjects":[[],[1,2]],"timelineGuides":false}}
```

- `tracks`：按肖像绑定顺序，为每个源人物写一条可区分的名词短语。优先用核实过的可见特征，并在有同框画面时补上相对位置或前后景。把方位限定在对应镜头（如开场双人镜头），人物换位或切到特写后仍沿用原轨迹。Subject 定义只说明源片里是谁，替换关系和范围写在 summary。
- `scope`：`face_only`（仅脸）、`head`（默认：脸、发型、眼镜）或 `appearance`（再含服装和穿戴配件）。
- `sourceAudio`：按 `<Video 1>` 是否含同步原声填写。`timelineGuides` 仅在片段已配置导帧时设为 `true`。
- `dialogueBinding`（可选）：填入从 1 开始的整数 `shot` 和 `subject`。仅在源片有同步原声且核实该镜头的说话人时填写；该人物必须出现在对应的 `shotSubjects` 中。
- `portraitAppearanceOnly`（可选布尔值）：若候选把参考照生成成镜头，可在受影响片段开启，明确肖像只提供外观，构图与背景沿用源片。
- `completeHairReplacement`（可选）：当耳后或后颈残留源人物发型时，可填从 1 开始的人物编号进行单变量复测。仅适用于包含发型替换的范围。
- `targetHairOutline`（可选）：核实肖像发型露出耳朵和颈部后，可填从 1 开始的人物编号，测试该轮廓。此字段取代 `completeHairReplacement` 的试验措辞。
- `shotSubjects`：从逐镜头源片检查记录按实际输入顺序生成，将可见轨迹 ID 映射为该段有序肖像绑定中的 1-based 编号。单人特写只填该人物，无待换人物填 `[]`。只有确认输入是单镜头且包含所有绑定人物时才可省略。
- `eyewear`（可选）：替换眼镜（`scope` 为 `head` 或 `appearance`）时，用与肖像等长的布尔数组标明每张肖像是否戴眼镜。
- `foregroundOccluder`（可选）：仅在源帧确认前景物件遮住待替换区域时填写简短物件名称；经过画面但未遮住替换区域时省略。
- `preservedPeople`（可选）：未选中人物在交叉或遮挡时容易被改写外观，传入已核实的源人物识别短语数组，为其补充沿用 `<Video 1>` 外观和可见性的保护句。
- `retainedDetails`（可选）：与 `tracks` 等长的数组（`string | null`），用于为某条轨迹补充直接影响可见动作的保留衣物或配饰说明。

六个节名、人物编号和句式由脚本统一生成。原样保存输出，修改时更新结构化输入并重新生成。发布前运行 `python3 "$SKILL_DIR/scripts/check_prompt.py" prompts.json` 检查结构。已有相同分段和输入的独立审定基线时，按相同片段 ID 导出节点提示词，运行 `python3 "$SKILL_DIR/scripts/check_prompt.py" saved-prompts.json --expected approved-prompts.json`；差异会指出片段和第一处变动的行。

模板在 `detailed_description` 中按输入顺序生成下列固定句式：

在这一栏只提供 `shotSubjects`，由模板输出镜头映射、原切镜和同一源人物轨迹。遮挡、眼镜与导帧仍由各自的结构化字段进入保留段。

```text
[Shot 1] <Subject 1> -> <Picture 1>, <Subject 2> -> <Picture 2>.
[Shot 2] <Subject 2> -> <Picture 2>.
Preserve the original cut between these shots in <Video 1>.
Shot 2 stays on <Subject 2>, the same source performer as in the opening shot.
```

## 分段提示词

跨段沿用人物对应关系，按每次请求的实际输入顺序更新肖像编号。源区间、时序、方向、替换范围和引用顺序相同时，逐字复用已验收且符合本规范的提示词。输入变化时，更新结构化输入、重新生成并对照新输入核对。

## 排查和验证

做提示词对照时，从基线原文出发，只修改一个结构化字段或措辞来验证一个假设。固定分段、有序素材版本、导帧、种子和模型参数。对照源片和基线检查同一人物、同一帧。

- 身份混用或漂移时，先查实际图片顺序和请求输入，再看首次出错处的切镜、遮挡、出画或续接。如果身份跟着屏幕位置走，改为绑定源人物轨迹。
- 服装或配饰变了，先核对计划中该特征的归属和 `retainedDetails`，再改提示词。
- 未选中的人物在交叉时发生变化，定位源片和输出中首次受影响的帧，将该人物的已核实识别线索加入 `preservedPeople` 后重新生成。

## 核对已保存的提示词

提交前，用 `opendirector project show` 或等效查询回读已保存的生成配置和有序引用。确认已保存提示词没有分镜指令，且每个 `[Shot N]` 标记与实际引用片段（含片段首帧）一致。普通标签按同一媒体类型的输入顺序解析，结构化标签按已保存的引用 ID 解析。对照计划检查六节、一对一对应、特征归属以及导帧配置。发现不一致先修正、重建并再次回读确认。

做提示词对照时，固定输入、模型和实际生效的部署设置。对照源片检查出错处，并按[检查结果与重试](workflow.zh.md#检查结果与重试)验收。
