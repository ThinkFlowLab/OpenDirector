# 视频分段

双人或多人镜头硬切至单人对白特写时，切点两侧分别规划生成结果。单人段从特写中人物可辨认的首帧起跑，保留原交付切点。模型输入长度不足时从相邻真实源片取上下文，组装时裁去。

如果已审阅的候选反复漏掉同一个已核实的硬切，把交付接缝固定在新镜头首帧，切点两侧采用独立生成结果。输入窗口可以重叠截取真实源片，以满足帧数对齐。从同一生成结果裁出两个区间无法恢复模型漏掉的切镜。在 `splitReason` 记录已观察到的失败。

## 先看原片

探测时长、帧率和帧数。除非用户指定其他帧率，使用恒定 24 FPS 的工作副本。需要转换时，用 FFmpeg 的 `fps=24` 等帧率滤镜并保持原播放速度。保留原视频和音轨，检查音画对齐，并用 `ffprobe -count_frames` 统计解码帧数。工作副本的帧率和解码帧数满足计划后即可使用。组装器对渲染后的片段做精确时长校验。只有输入容器的时长字段存在偏差时，无需重新编码。

检查完整源片和肖像。无法直接播放时，先做带时间戳的缩略图总览。已有一组帧号时，用 FFmpeg 的 `select` 滤镜一次解码并提取。在候选切点、人物进出画、交叉和遮挡处查看连续帧。无法检查画面时，说明哪一步计划受阻。

逐个检查候选切点紧邻的前后两帧，每个确认的镜头在检查记录中独占一行，短插镜和特写也单列。按该行画面填写可见的目标人物。切点两侧构图或可见人物有变化时，分别记录镜头和人物轨迹。相邻镜头可以共用生成窗口。以新镜头出现的第一帧为切点，包括开头模糊的帧。如果脸在更晚的帧才出现，直接保留中间的源帧。前后两帧不足以判断时，再向两边各解码一帧后保存切点。构图或可见人物突然变化时，先核对相邻帧，再判断是否为连贯运镜。对拟保留在同一镜头内的检测候选，逐个记录判定为切镜或连续运动的依据。检查每个边界两侧首尾的实际解码帧。短插镜或过渡帧里看不到替换范围内的特征时，直接保留这些源帧。即使相邻镜头在同一场景，只拍到替换范围之外特征的独立镜头也要单独列为原样保留区间。

- 镜头时间线记录源帧范围、切点、构图变化和动作。
- 人物可见性时间线记录源人物轨迹 ID、识别线索、进出画、遮挡和互动。把每个单人特写与能看清候选人物的同框画面并排对照，按一致的外观特征分配轨迹，并记录线索和帧号。有歧义时，找到足够的画面证据再绑定。

为每个实际送入模型的片段记录逐镜头检查结果。按输入播放顺序列出镜头（包括倒放和多截取的上下文），每行记录源帧区间、可见的待换人物轨迹 ID 和确认帧。无人需要替换时记录空集合。人物换位、短时遮挡或再入画时沿用同一轨迹。只有前景物件实际盖住待替换区域时，才记录物件名称、受影响轨迹和证据帧。将这些记录交给提示词构建步骤。

## 用已有结果选择方案

先检查当前项目是否已有可用计划，或用户是否为本次编辑指定了计划。能核对指纹时先核对，再检查切点、帧坐标和人物对应关系。替换范围和模型导帧行为也一致时，复用已验收的计划并绑定当前项目的素材和节点。新项目未提供现成计划时，根据看到的源片制定计划。

相同输入已经出现动作重复、身份丢失或切点偏移时，首版计划就应改对应窗口或接点。记录发现的问题、准备修改的内容和验收方式。保留接点需要的导帧。新素材按实拍切点和人物轨迹制定方案。

## 为多人替换选择片段

优先合并帧预算内、人物绑定可靠的相邻镜头。确需拆开生成时，在源片上检查接缝前后及实际送模首帧（包括倒放后的首帧）。切分处只要有待换人物可见但面部被手、道具、头发或其他人遮挡，就必须移到附近脸部清楚可辨的稳定帧，或把整个遮挡动作纳入同一个生成窗口。原片已有切镜和组装裁切可以留在窗口内部。单次生成窗口以约 5 秒为目标，按实际送入模型的帧数计算，包含上下文和导帧重叠。24 FPS 下，120 帧向上对齐到 124 帧。单次生成最多 6 秒（包括真实上下文和重叠）。超限的连续长镜头必须在稳定姿势处分段，按需规划重叠与导帧，并保持源片的完整动作和时序。 镜头内的分段边界应选在待替换区域完整可辨、人物轨迹明确、姿态稳定的源帧。人物进出画、脸被裁掉或关键特征被遮挡时，将边界移到前后可辨认处。相邻短镜头需要共享窗口时，保留原切镜及人物变化。

| 源片中的情况 | 分段做法 |
|---|---|
| 多位待换人物在同一连贯动作中可以辨认 | 模型支持时放在同一段，为每人建立独立的对应关系。 |
| 一位待换人物稍后入画 | 保留能辨认该人物的上下文。必要时单独划一段，或选更靠后的锚点。 |
| 待换人物离场，镜头继续 | 可在离场后的稳定处分段。留下的人沿用原对应关系。 |
| 人物交叉、重叠或交换道具 | 尽量将互动和身份线索放在同一段。必须拆开时，两侧都留上下文并检查接点。 |
| 同场景的相邻短镜头 | 优先共用一个生成窗口。按实际输入镜头顺序填写 `shotSubjects`，把原切点留在组装时间线上。 |
| 边界需要另开窗口 | 记录 `splitReason` 和具体依据。可用依据包括合并后超出帧预算、轨迹无法可靠绑定、找不到可辨认的接点，或已有对照结果显示合并会破坏动作或切镜。 |
| 同一人物被挡住后再次出现 | 有画面依据时，沿用原轨迹。 |

列出片段中任一时刻可见的待换人物及其在本段的进出画时间。保留未选中人物。待换人数超出模型参考数量限制时，调整方案或说明限制。

### 选择身份锚点和播放方向

对比可行的生成接缝和正反向实际送模首帧。在帧数预算和导帧约束内，优先选本窗口待换人物同框最多、脸部清楚、姿态稳定的帧。记录候选帧号、可辨认的轨迹 ID 和选择依据。没有可行的齐人帧时，选最清楚的可行帧并写明限制。原片切点仍留在组装时间线。

相邻生成窗口允许重叠。先选人物齐全的实际送模首帧，再向前或向后取连续原片音画，覆盖需要交付的帧；必要时倒放完整窗口。每个送模窗口仍须满足模型帧数要求（至少 107 帧，按 `17k+5` 对齐）和六秒上限。组装时按各自的保留区间裁掉上下文与重叠，每个源帧只交付一次。

续接时，把上游导帧的两个原始索引换算成源帧，按实际播放方向对齐下游输入第 0、21 帧。逐张核实可辨认的待换人物。多人窗口中，同一个待换人物若两张导帧都不可辨认，重排输入窗口和接点，或在齐人处设独立锚点。找不到可行方案时，报告限制并等用户确认。

裁切前检查每个候选锚点窗口的两端，记录源帧号和可辨认的待换人物。遇到模糊、遮挡或切点时查看相邻帧。人物陆续入画时，也考虑靠后的窗口。

选出能明确绑定人物和肖像、同时能接上相邻片段的端点。从较早一端开始就正序生成，从较晚一端开始就倒序发送整个输入窗口，包括上下文。两端都清楚时按接点选择。两端都无法辨认时检查其他窗口。

每个核实过的连续镜头声明一个免导帧的锚点。同一镜头内的其余生成段都需要导帧。前面的片段可反向续接，后面的片段可正向续接。记录选定的端点、可见轨迹和方向依据。分组从本次执行的上游原始结果为下游取导帧。

## 制定可执行的分段计划

裁切或创建生成节点前，在执行目录保存 `segment-plan.md`。在开头按 `frame-plan.json` 写明标准化源素材、交付总帧数、帧率和音轨策略。记录模型设置及用于生成的原声区间。每个保留区间记录源帧范围、镜头、边界理由和组装区间。

在计划顶部放一个等宽 ASCII 图，从最终帧计划抄录真实数据。图中按源片顺序列出半开区间，标明原片直通、共用的生成窗口、实际送模区间、锚点、续接方向和导帧来源。行太宽时按场景拆成多行。下图只说明格式。

```text
Source order:    [0,6) [6,48) [48,96) [96,102) [102,144)
Delivery:        SRC   W1     W1      SRC      W2
Model inputs:    W1 [6,113)    W2 [80,187)
Generation:      W1 (anchor) --[guide 74,95]--> W2 (forward)
```


- `Keep source` 标记原样保留的镜头，包括只有一帧的插入镜头。按原切点把源片放在最终时间线上。生成窗口可包含该镜头作上下文。
- `Generate` 还需记录人物与肖像的对应关系、替换范围、方向和依赖、导帧来源及原始帧索引、上下文与重叠、请求时长和原始帧数，以及反转前缀和输出保留区间。

使用半开区间 `[start, end)`，注明是源帧、原始输出帧还是组装帧。整段编辑时，从首帧到末帧按原切点覆盖一次。

分别记录模型输入区间和成片保留区间。输入不够长时，在源片时间轴上向后截取连续的真实音画，达到模型要求的帧数。片尾没有足够的后续帧时，将窗口起点移到更早的稳定帧，或与前一段合并后重新校验。禁止用复制帧、冻结、循环或补静音凑长度。组装时裁去仅作上下文的画面。移动或反转窗口后，从源帧坐标重算保留区间及导帧索引。核对保留画面的首尾帧、原切镜和原样直通区间。

- 计算保留画面、上下文和重叠所需的原始帧数。MiniMax-H3 和 FastH3 参考生成使用同时满足帧预算和模型最短时长的最小 `17k + 5` 帧数。24 FPS 下，4 秒最低时长向上对齐到 107 帧，约 4.458333 秒；5 秒对应 120 帧，向上对齐到 124 帧。超出 6 秒上限（24 FPS 为 141 帧）时另选动作边界。
- 审阅分组结果时，核对每个已采纳输出的实际帧数和帧率。导帧使用原始输出帧索引。根据实际动作和切点检查计划的保留区间。修正保留区间时，一次裁去确认过的重叠和仅作上下文的画面。
- 独立的 vLLM-Omni 缓存 latent `continuation` 模式（不走 `group.publishRun`）在 `17k + 5` 模型窗口内包含不可见重叠，按每组 17 帧输出新画面。

长镜头里有多次独立手势或可见人物发生变化时，生成前在姿势稳定处划分较短的导帧续接窗口。既有结果出现动作延迟或重复时，逐帧对照源片和结果，找到时序开始偏离的位置。优先在该动作之前拆成较短的窗口，用导帧续接。在姿势和构图相符处拼接，再核对成片动作是否在源片对应时刻只出现一次。

## 源片段保留原声

用帧区间裁切视频，音轨使用同一源片时间区间。裁切后重置音画时间戳，编码完成后探测帧数和音画时长。

源片有原声时，每个送生成的源片段都保留同步内嵌原声，包含真实上下文和导帧重叠区间。反向生成时一同反转已裁切的音画。导入前探测音轨，检查与画面时长差不超过一帧，并满足部署时长限制。发现音画不齐时，重新按同一源片区间裁切并探测。成片音轨在时间线上单独设置。

## 准备执行计划

帧计划通过后，为各生成段[写提示词](prompt-writing.zh.md)。多段任务先[搭建画布](workflow.zh.md#2-搭建画布)，再[发布分组和可读的计划节点](workflow.zh.md#发布并核对计划)，然后启动。只要求计划时交付 Markdown。

### 校验帧归属

将 `frame-plan.json` 与 `segment-plan.md` 保存在同一目录。

- `totalFrames` 是标准化源片的总帧数。`sourceOnly` 列出原样保留的区间。
- `delivery.fps` 是时间线的整数帧率。音轨绑定到分组时间线后，在 `delivery.audio.asset` 记录交付音轨的精确版本。
- 每个 `segments` 条目记录 `id`、输入范围 `source` 和请求的 `rawFrames`。需要反转时记录 `reverseLimit`。记录计划的锚点或导帧，画布建好后记录各生成节点的 `itemId`。
- 每个 `timeline` 条目记录 `source` 范围和 `owner`，后者为 `source` 或 `generated`。生成条目还需记录 `segment` 和反转后的 `keep` 区间。校验保存的时间线前，根据已核对的源素材、任务结果或裁切回执补上各片段的精确 `asset`。裁切或反转素材使起始帧改变时，记录 `assetInFrame`。源画面默认取 `source` 起始帧，生成画面默认取 `keep` 起始帧。`AssetRef` 包含 `assetId`、`revision`、`fingerprint` 和 `kind`。

先保存 `shot-inspection.json`，再决定生成窗口和组装方式。记录 `totalFrames` 和 `shots`，按顺序覆盖整个源片。每行填写 `source: [start, end]` 和 `selectedTracks`，后者只列该区间内看得见、且特征属于替换范围的人物 ID。原样保留的区间写 `selectedTracks: []`。这些区间即使作为生成上下文，成片仍取源片。相邻镜头的 `selectedTracks` 集合发生变化时，校验器自动要求设置组装边界。其他经确认也必须独立组装的切点，在后一镜标记 `requiredTimelineCut: true`。只有源片帧提供了修正依据，才改镜头检查记录。换人预检还要求 `sourceFingerprint`（标准化完整源片的 `sha256:` 指纹），以及按稳定轨迹 ID 索引的 `identityMap`。每条轨迹记录 `cue`（已核实的英文源人物识别线索）与 `portrait`（固定肖像的 `AssetRef`）。每个镜头用 `trackFrames` 把每条待换轨迹映射到该镜头内可辨认的源帧。单独查看实际解码的首帧、末帧和每个切点前后两帧，包括单帧插镜。替换范围外的帧独立列为原片直通区间。用 `frameTracks` 按准确源帧号记录各段实际送模首帧及两张续接导帧上可辨认的轨迹，无法辨认时填 `[]`。锚点首帧至少有一位明确可辨认的待换人物，优先选齐人且脸部清楚的画面并比较正反放。两张导帧须合计覆盖所有待换人物。在 `segments` 的每段填写 `portraits`（固定肖像槽位顺序下的轨迹 ID）、`clip`（本地送模片段路径），导入后填写 `video`（该视频的精确 `AssetRef`）。

组装切点两侧可引用同一个生成节点，并各自填写保留区间。直通区间仍使用原片。相同源片窗口、帧数、方向、人物和导帧共用一次生成。若多个生成窗口各自只交付不到原始生成帧数的一半，发布前逐段写明不能合并的原因。 将核实的面部遮挡写入 `occludedFaceRanges`，逐项填写半开 `source: [start, end]` 区间及已绑定的 `track` ID。确认没有遮挡后才填 `[]`。先运行下方校验再裁切。校验会拒绝生成接缝两侧或实际送模首帧有遮挡，并检查同一组有序肖像的相邻顺放锚点能否通过平移共用真实输入窗口，原样直通区间可留在窗口内部。短续接尾段要检查能否在保留导帧重叠的前提下移动接点、重新分配保留帧。移动后重算导帧和裁切。

裁切或发布计划前，运行 `python3 "$SKILL_DIR/scripts/validate_frame_plan.py" frame-plan.json --enforce-window-limit --inspection shot-inspection.json --normalized-source "$NORMALIZED_SOURCE"`。`SKILL_DIR` 是本技能目录，`NORMALIZED_SOURCE` 是未裁切的工作副本。`totalFrames` 取该副本的实际解码帧数。本地帧计划用于记录画面检查和交付核对。已发布的 `runPlan` 是执行输入，应与本地帧计划一致。[检查解码后的结果](workflow.zh.md#检查结果与重试)，核对人物、导帧和时序。
