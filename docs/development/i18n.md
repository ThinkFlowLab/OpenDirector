# 中英双语界面

界面语言在 `zh-CN` 与 `en-US` 之间切换。中文是默认语言，也是词条键的基准；英文必须覆盖同一组键。

## 语言选择

- 用户可以在画布左上角的「中文 | EN」开关直接切换，也可以使用「设置 → 界面语言」。
- 用户在「设置 → 界面语言」保存的选择优先。
- 没有保存值时，浏览器语言以 `zh` 开头使用 `zh-CN`，以 `en` 开头使用 `en-US`，其他语言使用英文 `en-US`。
- 选择保存在 `localStorage` 的 `opendirector.locale.v1`，并同步到 `<html lang>` 与 `data-locale`。
- 界面语言不影响 Agent 回复语言。Agent 始终跟随用户最新提问的语言，不参考当前界面语言。

实现入口：

- [locale.ts](../../src/i18n/locale.ts)：检测、读写、文档语言属性。
- [I18nProvider.tsx](../../src/i18n/I18nProvider.tsx)：React Provider、`useI18n()`、`useT()`。
- [messages.ts](../../src/i18n/messages.ts)：合并中英文目录。
- [index.html](../../index.html)：首屏加载前设置语言，避免闪烁。

## 目录结构

```text
src/i18n/
  types.ts                  Locale、MessageKey、MessageEntry、参数类型
  locale.ts                 语言检测与持久化
  format.ts                 占位符与复数插值
  I18nProvider.tsx          Provider 与 hooks
  messages/
    zh-CN/                  基准目录，一个功能一个文件
    en-US/                  同键英文目录
```

词条使用扁平语义键，例如 `timeline.track.video`。中文文案逐字保存在 `zh-CN`，不得在组件里另写一份；英文按语义翻译，不照搬中文语序。

占位符使用 `{name}`。英文数量使用 `{ one, other }`：

```ts
"library.selectedCount": {
  one: "{count} item selected",
  other: "{count} items selected",
},
```

## 新增或修改文案

新功能先建立自己的词条文件：`zh-CN/<feature>.ts` 与 `en-US/<feature>.ts`，并在两个 `index.ts` 中注册，避免把多个功能堆进同一文件。已有功能在对应文件增改。

1. 在对应 `zh-CN/<feature>.ts` 增加键，值保持现有中文不变。
2. 在 `en-US/<feature>.ts` 增加同名键，写自然英文。
3. 组件使用 `const { t } = useI18n()` 或 `const t = useT()`；非组件纯函数使用可选的 `t: Translate = defaultTranslate` 参数，或返回 `MessageKey` 由渲染层翻译。
4. 不翻译用户内容、项目/节点名、提示词、文件名、模型名、ID、键盘按键、CSS 与协议枚举值。
5. 稳定业务值（如 `auto`、工具 id、节点类型、音色 id）保持原值，只在显示层翻译。
6. 若文案出现在模块初始化阶段，用 `tNow()`；它的语言由 Provider 同步。

## 新功能接入清单

新功能交付前逐项确认：

1. 词条文件已在 `zh-CN` 与 `en-US` 成对创建，并在两个 `index.ts` 注册。
2. 界面文案全部通过 `useI18n()`、`useT()` 或 `tNow()` 取得；数组、状态机和校验结果返回 `MessageDescriptor`，不在组件内拼句子。
3. 后端新增错误码或状态时保持 `code` 稳定，并在 [localization.py](../../apps/api/src/opendirector_api/localization.py) 的 `ENGLISH_BY_CODE` / `ENGLISH_BY_STATUS` 补齐英文；中文文案在抛出点，前端显示层映射同步更新。
4. 新增工具目录、模型简介、生成失败原因、任务状态或历史预览标签时，扩展「当前剩余」列出的显示层查找表，不直接把中文写进数据目录。
5. 更新下方审校表；新功能没有独立文件时，确认现有文件已经覆盖新增词条。
6. 运行 `npm run check:i18n`，再实际切换中英文走一遍新增流程；自动检查不覆盖硬编码英文，也不能证明英文界面没有中文泄漏。
7. 用户可见文档随功能同步中英文版本；开发内部文档优先使用英文。

## 后端与错误

浏览器请求带 `Accept-Language`。API 的错误码、状态码和用户可见状态由 [localization.py](../../apps/api/src/opendirector_api/localization.py) 选择中英文文案；业务码本身不变，客户端仍可按 code 分支。

前端校验与领域错误直接进入界面时，也必须走词条；新增错误应同时提供中英文。

## 检查

```bash
npm run check:i18n
```

检查两件事：

- `zh-CN` 与 `en-US` 的键集合必须完全一致。
- 源文件中的中文行数不得超过 [i18n-baseline.json](../../scripts/i18n-baseline.json) 的记录。该基线只应下降；确实需要新增中文时，先完成翻译，或明确更新基线并在评审中说明。
- 浏览器脚本的页面语言由脚本固定为 `en-US` 或 `zh-CN`，断言文案必须与固定语言一致；`npm run check:browser-locale` 检查这条约定。

自动检查不覆盖组件里硬编码的英文，也不覆盖跳过目录的数据标签；这些按「新功能接入清单」评审，并实际切换两种语言核对。

## 当前剩余

`check:i18n` 的基线为 168 行，剩余中文都属于数据或历史兼容内容，不是未翻译的界面控件：

- `toolCatalog.ts`：静态工具目录的标题、字段与选项。界面通过 `toolText.ts` 在显示层翻译；目录数据保持稳定，避免业务值随界面语言变化。
- `assets.ts`：示例工程内容按界面语言生成中英文两套（`EXAMPLE_COPY`），创建后作为用户内容保留，不再随语言切换改名。`NodeComposer.tsx`：旧模型 id 与演示音色 id 是历史兼容值，显示时另行翻译。
- `generationCatalog.ts`：旧版模型目录的观察备注与价格说明，当前主界面不渲染这些字段。
- `model.ts`：`LOCAL_DEMO_MODEL` 是旧工程沿用的稳定模型值，不是显示名称；界面显示时翻译。
- `dataBoundary.ts`：3 处 `"自动"` 是读取旧工程时的迁移字面量，必须保留以识别历史数据。
- 其余为代码注释。新增中文注释也会计入基线；如只是注释，可直接改为英文以避免占用额度。

持久化的后端状态与静态数据标签在显示层翻译：生成失败走 [generationFailureText.ts](../../src/canvas/generationFailureText.ts)，工具任务进度与错误走 [toolTaskText.ts](../../src/canvas/toolTaskText.ts)，工具不可用原因走 [toolReasonText.ts](../../src/canvas/toolReasonText.ts)，工具目录走 [toolText.ts](../../src/canvas/toolText.ts)，服务商预设与模型简介走 [providerPresets.ts](../../src/canvas/providerPresets.ts) 和 [modelDescriptions.ts](../../src/canvas/modelDescriptions.ts)，历史预览标签走 [creationPreviewText.ts](../../src/canvas/creationPreviewText.ts)，Agent 工具错误走 [assistantToolText.ts](../../src/canvas/assistantToolText.ts)。这些查找表由 `check:i18n` 跳过，新增后端状态或目录项时应同步补充。

迁移新的用户可见文案时沿用本文件的结构，不另建平行词条表。
